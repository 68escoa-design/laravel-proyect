# GUÍA PARA POSTMAN - SISTEMA DE GIMNASIO

## CONFIGURACIÓN INICIAL

1. Crear una nueva colección en Postman llamada "Gimnasio API"
2. Configurar la URL base: http://127.0.0.1:8000/api
3. Configurar una variable de entorno para el token: `{{token}}`

## AUTENTICACIÓN

### POST /api/login
**Descripción:** Iniciar sesión y obtener token de autenticación

**Body (JSON):**
```json
{
  "email": "admin@gimnasio.com",
  "password": "password"
}
```

**Usuarios de prueba:**
- Admin: admin@gimnasio.com / password
- Trainer: trainer@gimnasio.com / password  
- Cliente: cliente@gimnasio.com / password

**Respuesta esperada:**
```json
{
  "user": {
    "id": 1,
    "name": "Admin",
    "email": "admin@gimnasio.com",
    "role": "admin"
  },
  "token": "1|aBcDeFgHiJkLmNoPqRsTuVwXyZ1234567890"
}
```

**IMPORTANTE:** Copia el token y guárdalo en la variable de entorno `{{token}}`

## ENDPOINTS PARA ADMIN

### CLIENTES

#### GET /api/clients
**Headers:** 
- Authorization: Bearer {{token}}

**Descripción:** Obtener todos los clientes

#### GET /api/clients/{id}
**Headers:** 
- Authorization: Bearer {{token}}

**Descripción:** Obtener un cliente específico

**Headers:**

## ESTRUCTURA DE LA BASE DE DATOS

### Tablas principales:
- users (usuarios del sistema)
- clients (información adicional de clientes)
- plans (planes de suscripción)
- client_plans (asignación de planes a clientes)
- payments (pagos realizados)
- exercises (catálogo de ejercicios)
- routines (rutinas asignadas)
- routine_exercises (ejercicios en cada rutina)
- schedules (horarios disponibles)
- attendance (registro de asistencia)

---

## NOTAS IMPORTANTES

1. **AUTENTICACIÓN:** Todos los endpoints (excepto /login) requieren el token en el header:
   ```
   Authorization: Bearer {{token}}
   ```

2. **ROLES:** El sistema verifica roles automáticamente:
   - Admin: acceso total
   - Trainer: acceso a rutinas y clientes
   - Cliente: acceso solo a su información

3. **ERRORES COMUNES:**
   - 401: Token inválido o expirado
   - 403: No tienes permiso para este endpoint
   - 404: Recurso no encontrado
   - 422: Error de validación en los datos

4. **BASE DE DATOS:** Actualmente usa SQLite. Para producción usar MySQL:
   - Cambiar DB_CONNECTION=mysql en .env
   - Configurar DB_DATABASE, DB_USERNAME, DB_PASSWORD
   - Ejecutar migraciones: php artisan migrate
