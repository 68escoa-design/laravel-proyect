## 📊 TABLAS Y CAMPOS DETALLADOS

### 1. USERS (Usuarios del sistema)
**Propósito:** Almacenar información de autenticación y roles

| Campo | Tipo | Descripción | Restricciones |
|-------|------|-------------|---------------|
| id | BIGINT (PK) | Identificador único | AUTO_INCREMENT |
| name | VARCHAR(255) | Nombre completo del usuario | NOT NULL |
| email | VARCHAR(255) | Email del usuario | UNIQUE, NOT NULL |
| email_verified_at | TIMESTAMP | Fecha de verificación de email | NULLABLE |
| password | VARCHAR(255) | Contraseña encriptada | NOT NULL |
| role | ENUM('admin','trainer','client') | Rol del usuario | DEFAULT 'client' |
| remember_token | VARCHAR(100) | Token para recordar sesión | NULLABLE |
| created_at | TIMESTAMP | Fecha de creación | Automático |
| updated_at | TIMESTAMP | Fecha de actualización | Automático |

**Relaciones:**
- HasOne: Client (para usuarios con rol 'client')
- HasMany: Routine (como trainer para usuarios con rol 'trainer')

**Índices:**
- PRIMARY: id
- UNIQUE: email

### 2. CLIENTS (Información adicional de clientes)
**Propósito:** Almacenar datos específicos de los clientes del gimnasio

| Campo | Tipo | Descripción | Restricciones |
|-------|------|-------------|---------------|
| id | BIGINT (PK) | Identificador único | AUTO_INCREMENT |
| user_id | BIGINT (FK) | ID del usuario relacionado | FOREIGN KEY -> users(id), ON DELETE CASCADE |
| phone | VARCHAR(20) | Teléfono del cliente | NULLABLE |
| address | VARCHAR(255) | Dirección del cliente | NULLABLE |
| birth_date | DATE | Fecha de nacimiento | NULLABLE |
| registration_date | DATE | Fecha de registro | DEFAULT CURRENT_DATE |
| active | BOOLEAN | Estado del cliente | DEFAULT TRUE |
| created_at | TIMESTAMP | Fecha de creación | Automático |
| updated_at | TIMESTAMP | Fecha de actualización | Automático |

**Relaciones:**
- BelongsTo: User
- HasMany: ClientPlan, Payment, Routine, Attendance

**Índices:**

## 🔗 DIAGRAMA DE RELACIONES

```
users (1) ----< (1) clients
users (1) ----< (N) routines (como trainer)

clients (1) ----< (N) client_plans
plans (1) ----< (N) client_plans

clients (1) ----< (N) payments

clients (1) ----< (N) routines
users (1) ----< (N) routines (como trainer)

routines (1) ----< (N) routine_exercises
exercises (1) ----< (N) routine_exercises

schedules (1) ----< (N) attendance
clients (1) ----< (N) attendance
```

## 📝 REGLAS DE INTEGRIDAD

### FOREIGN KEYS
- **ON DELETE CASCADE:** Cuando se elimina un registro padre, se eliminan automáticamente los registros hijos
- **NOT NULL:** Campos obligatorios que no pueden ser nulos
- **UNIQUE:** Campos que deben tener valores únicos

### VALIDACIONES DE NEGOCIO
- **Role:** Solo puede ser 'admin', 'trainer', o 'client'
- **Status de attendance:** Solo puede ser 'present', 'absent', o 'late'
- **Payment method:** Valores comunes: 'cash', 'card', 'transfer'
- **Active:** Campos booleanos para controlar estado de registros
